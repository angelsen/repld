# Test phases

The phase list of `tests/smoketest.py`; the root `CLAUDE.md`'s "Testing" section holds how the suite runs. A case added to a phase is named in that phase's line here.

Phases:
- **2:** Pure logic called directly, no kernel (`tests/phases/pure.py`) — `check_arguments`, `form()` field subset, gist tool-name rules, the instructions budget, gate coercion, `_split_answer`, `_make_preview`, `render.py`, `_format_args`, `resolve_socket_path`'s `AF_UNIX` length refusal, the seat-pid claim gates (`bridge._seat_pid`, `rebind_cmd._own_seat_pid`, `ipc._caller_chain`, `bind.rebind_exec` exporting the pre-exec parent for the `bridge` subcommand only), the `ps` ancestry reads over a real process chain (read at `/bin/ps`, whatever `ps` is on `PATH`), the macOS table's parse (a `comm` with spaces, a malformed line skipped) and its fork count (one per walk and per `claude` check, whatever the depth), a register and a rebind over six connections each reading `ps` once, the boot-time `RLIMIT_NOFILE` target and its raise from a 256 soft limit. `repld.testing`'s stand-in and `NotInKernelError`. New pure functions get their cases here, not an end-to-end route.
- **3:** Core MCP plumbing — initialize (version negotiation), ping, tools/list, sync exec, deferred exec, get_task polling (incl. `structuredContent`/`outputSchema` conformance), tool arguments checked against `inputSchema` and refused in-band (`core_schemas.check_arguments`: unknown, missing, wrong type, outside the enum), JSON-RPC edges (a null-id `ping` unanswered, `-32700`/`-32600` for malformed lines), a client `notifications/cancelled` stopping an `exec`, a `REPLD_CODE_MODE=1` bridge's script-shaped `exec` results next to a plain bridge's unchanged ones, plus three guards on input nobody writes on purpose: bridge/gist argv validation, a malformed gist-registry JSON root, an AST sweep for monkeypatched names nobody resolves through, and one for task spawns (every `create_task`/`bg.spawn` in the package keeps its handle and carries a literal `repld-` name, the two rules `bg.py` and `kernel._watch_block` state).
- **4:** Channel notifications — task_done push, notify() from user code, pre-gate queuing.
- **5:** Single-kernel flock mutex, `repld_init.py` bootstrap (hand-started kernel, `repld restart`, both lazy-spawn waiters), runtime-state permissions, `pid_alive` seeing through a zombie, `is_same_process` telling a pid's later holder apart, a directly spawned kernel reaped on exit, spill eviction, boot sweep reclaiming a dead kernel's whole project dir, `gists.add_search_dir()` (bootstrap-wired third gist tier).
- **6:** Tool registration, gist auto-reload, browser integration (Chrome 140+; `smoketest.py` spawns a throwaway headless instance via `harness.ThrowawayChrome`; with none available the run fails, so leave 6 out of `--phases` on a machine without Chrome), in `tests/phases/browser.py` — PNG/HAR/selector/injected-engine/Chrome-backed coverage; full case-by-case rationale in `CLAUDE-ARCHIVE.md`.
- **7:** `defer()` — fire-and-forget with channel push on completion; the coroutine's return value recoverable both via the push and `get_task`'s `result`; `no_display()` suppresses the print but not the recovery.
- **8:** Gist resources — `resources/list`/`resources/read repld://gists/{name}`; two AST-only doc-drift guards (agent-facing `help.py` API surface, hand-written docs' API usage).
- **9:** Gist-registered MCP tools — `_tool_*` discovery, schema inference, dispatch, auto-reload, error handling, stale `__repld_tools__` reading as inert, `tools/list_changed` on tool add/remove.
- **10:** `@every(seconds)` decorator — periodic ticker, immediate first tick, `delay=`, error survival, `cancel()`/`cancel_all()`, exec-cell ticker attribution, `every(tab=)` refusing registration with no browser builtin.
- **11:** Graceful shutdown — `_shutdown` drains `@every` + `defer()` `try/finally` blocks within a 2s budget.
- **12:** Cross-project gist links — `add_link` (registry + AST sibling co-link), `./gists/.links` manifest, stale-entry skip/prune, co-link refusal, registry `(already here)` marking, `gist lint`'s `deps` rule recognizing linked siblings, `add_link`'s kernel-only-import warning.
- **13:** Session registry — boot writes `sessions/<pid>.json`, `list_sessions()`, removal on SIGTERM.
- **14:** Dashboard HTTP — header-count bound, `Connection: close`, Host allowlist (DNS-rebinding guard), `GET /` auth + token non-leak, per-port cookie, `POST /api` Bearer-only, per-session sessions-RPC tokens.
- **15:** Headless kernel — discovery spawns nothing, the JSON-RPC edges of phase 3 answered by a bridge with no kernel, lazy spawn + heal across kernel death, MCP discovery from `kernel.cache`, targeted vs. broadcast push (incl. `push_delivered`), event log/status/tasks/unknown-method handling, restart refusing reattach, `ipc.rebind_claude_session` (process-tree match, survives respawn, a repeat rebind arms nothing, a refused repeat still hands the old id's owed pushes to the connection carrying the new one, and so does the hook's rebind with no `old_id` after a bridge restart under the same claude), `ipc.list_claude_connections` (claude pid per bridge), `ipc.park_pushes`/`unpark_pushes` (holds a push until rebind or an explicit unpark flushes it, its own timeout force-delivers with no rebind, `push_delivered` reads null while held and flips true/false on the actual flush), `--project`/`--project-git` (worktree joins the main checkout's kernel, refusals, restart from elsewhere, lookups creating no dir), `repld start` (cold spawn, idempotent), racing boots collapsing to one kernel, a seat pid claimed where the tree reads empty (bridge claim, `repld rebind` hook leg, pending id).
- **16:** Project-venv binding — `./.venv` detection, version-matched `adopt()`, cross-version refusal, `REPLD_BOUND` sentinel, systemd-unit spawn (cgroup/reparenting/racing boot).
- **17:** Human gates on a headless kernel — `awaiting_human` push + answer command, `repld gate --json`, answer/reject/choose/ask semantics, unknown-id error, `ask` on a pinned tab, the dashboard's `gates`/`gate_answer` RPCs (Bearer-only, same coercion, first answer wins).
- **18:** `repld tasks wait`/`cancel` — blocking wait on an already-done and a still-running task, exit code + exception text on a failed task, unknown-id error, cancel of a running vs. already-done task, `cancel` actually stopping the task, plain listing unaffected.
- **19:** Peers (kernel-to-kernel calls) against two to five real kernels, plus `host:target` peers through a stand-in `ssh` on kernel A's `PATH` (name and path targets, typed errors, a failed ssh never ran, `gather`, hangup cancel, `start=True`, later calls riding a socket forward, a dead forward probed and rebuilt, a refused one not retried): bootstrap wait, name/path handles, `info`/`inspect`, typed errors with the never-ran / ran / unknown split, payload limits, caller identity (call, event log, `get_task`, `tasks --json`, nested chain), a callee calling its caller back on its own chain (refused as a cycle when deferred from the registering call), `gather` concurrency, a blocking sync callee not stalling the callee's loop, deferred value push, cancellation by `asyncio.timeout` and MCP `cancel`, cycle and self refusal, death mid-call (SIGKILL, a held loop, a graceful stop) never retrying, a cold peer erroring unless `start=True` (cleaned env), `gist stub` forwarding / `--check` drift / `--force` never clobbering a hand-written gist. Pure cases (resolution, chain vetting, reply mapping, stub rendering and forwarding) sit in phase 2.
- **20:** Gates under a real `claude -p` and `claude --bg` (`tests/phases/live_claude.py`): costs API money, so it runs only when named (`--phases 20`) and skips with no `claude` on PATH. A `-p` run exits with its confirm gate still pending, the CLI answers it, and the push for the departed session is queued; a `--bg` worker's cell is `origin_kind` `bg`, and the CLI answer completes it with the push written to the worker's inbox. The project dir sits under the gitignored `.live.local/` because `--bg` only inherits workspace trust from a parent.

Full per-case rationale for every phase (why each specific assertion exists, not just what it covers) lives in `CLAUDE-ARCHIVE.md` (at the repo root) — read it before extending a phase, not every session.
