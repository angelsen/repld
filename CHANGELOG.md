# Changelog

All notable changes to this project will be documented in this file.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- **AX-tree diff in observations.** Every observed mutation now leads with a `changes:` section — what the action made appear, disappear, or change state (`+ button 'port' ×3`, `- link 'Bye'`, `~ button 'Save' [disabled] → [none]`), aggregated with multipliers and capped at 12 lines. `pre_observe` snapshots the same AX traversal the tree renderer walks (same roles, same depth), so the diff describes exactly what a reader of the two trees would see change; `changes: none` means the page visibly ignored the action. Suppressed across a navigation (the whole tree is new) and on `browser_open` (no pre state). This is the screenshot round-trip eliminated: "did that click do anything" is answered in the same call.
- **`browser_drag` / `Tab.drag(source, to, steps=, duration_ms=)`** — press, paced `mouseMoved` events with `buttons=1` held, release, atomically in one call; gesture state can't survive being split across MCP round trips (a 6 px SVG port-drag proved unwinnable as discrete calls). Endpoints are selectors (strictly resolved, scrolled into view) or `(x, y)` / `'x,y'`. A drop zone that only mounts on dragstart is handled: an unresolvable `to` defers past the press and re-resolves mid-gesture. The release always fires (`finally`, at the last point reached), so an error never leaves the page mid-drag. Receipt names both endpoints and warns on an occluded drop point.
- **`browser_hover` / `Tab.hover(selector)`** — park the pointer on an element and leave it there: `:hover` styling and mouseenter-revealed UI stay up for a following click, and the `changes:` diff reports what the hover revealed.
- **Type-to-filter in `select_option`.** When the click focuses an element declaring `aria-autocomplete`, the option text is typed into it and resolution runs against the filtered listbox — the only route to an option a virtualized list keeps below its render window (found live: "Eskalert" below the render window of Jira's Replace-status picker, where the option-miss digest could only list the first 20 global statuses). The receipt says `(typed to filter)`.
- **`Tab.keys([...])` + `browser_key keys=[...]`** — a whole keyboard flow (`["Ctrl+A", "Backspace", "ArrowDown", "Enter"]`) in one call instead of one round trip per keypress; `delay_ms` between presses for apps that debounce.
- **Modifier combos in `key()`** — `"Ctrl+A"`, `"Shift+Tab"`, `"Cmd+C"` (Ctrl/Control, Alt, Shift, Cmd/Meta; a trailing `+` is the plus key), and single printable characters.

### Fixed

- **Editing keys did nothing.** `key("Backspace")` fired keydown/keyup but deleted nothing; arrows never moved the caret. Chromium's editing actions dispatch on `windowsVirtualKeyCode`, which repld never sent — only Enter/Space worked, and only because 0.2.9 gave them `text`. Named keys and printable characters now carry their VK code (subset of Playwright's USKeyboardLayout).

## [0.3.2] - 2026-08-20

### Added

- **Playwright locator calls accepted as selectors** — `getByRole('button', { name: 'OK' })`, `getByTestId('x')`, `getByText`/`getByLabel`/`getByPlaceholder`/`getByAltText`/`getByTitle`/`locator('#id')` — so the strict-mode ambiguity error's own `aka getBy…` suggestions paste back in as-is. Simple single-call forms only; chains error with guidance. Semantics mirror Playwright's `locatorUtils` builders (case-insensitive by default, `exact: true` honored).
- **`placeholder=` and `testid=` selector forms** — both existed in the engine, now one translation each away.
- **`viewport=` on `browser_open`** (`"1440x900"`) and **`Tab.set_viewport(width, height)`** — fixed viewport at `deviceScaleFactor: 1`, so screenshot coordinates are page pixels; replaces the manual `Emulation.setDeviceMetricsOverride` dance.

### Changed

- **`browser_request` caps cookie and long header values by default** — the cookie jar and bearer tokens dominated every request dump (~150 lines of JWT per capture). Noise control, not redaction: cookie *names* stay visible, values over the cap show a head + `…(+N chars — full=true for the rest)`, and `full=true` (or `tab.request(id)` in exec) returns everything verbatim — repld's contract that the agent works with the user's real sessions is unchanged.

### Fixed

- **Clicks scroll the target into view first (`DOM.scrollIntoViewIfNeeded`).** Quads are viewport coordinates, so an element below a scroll fold — the page's or a scrollable listbox's — reported a center outside its container's clip, and the dispatched click landed on whatever was actually at that point. Found live on an Atlaskit Replace-status modal: selecting an option below the react-select menu's fold passed the visibility check (clipping isn't visibility), clicked the modal's blanket, and closed the dialog — reported as "the dialog closed without confirm". Fixes every below-the-fold click, not just menus.
- **`select_option` waits for a just-opened menu to stop moving** before clicking the option: Popper repositions the listbox after first paint, and rAF-scale stability passes inside that window. The option's center is sampled 120 ms apart until it settles (1.5 s bound).
- **`select_option` verification reads what the widget renders.** The verify step checked only the resolved field element's `value`/`textContent`; react-select renders the choice into a sibling inside the control — and puts `role=combobox` on the *input itself*, so a `closest()` walk self-matches. Verification now walks up to the value container, so a landed selection verifies and a closed-dialog no-op honestly reports "(selection not verified)".
- `type_text(sel, "")` clears reliably — guarded by a test: zero keystrokes leave the value unchanged, which is exactly the signature the verify-and-fallback path reads as "controlled input swallowed it", so the native setter writes the empty string. (The pre-engine bug: select-all-then-type-nothing left the old value selected but intact.)


## [0.3.1] - 2026-08-20

### Fixed

- **Non-ASCII selectors matched nothing.** Selector translation quoted user text with `json.dumps`' default `\u`-escaping, which the engine's selector parser reads as literal characters — `text=Pågår`, `label=Fødselsdato`, and any role name with a non-ASCII character silently missed while the aria snapshot listed the element. Found field-testing 0.3.0 against a Norwegian Jira workflow editor. Now `ensure_ascii=False` everywhere the translation layer quotes text (`text=`, `label=`, role names, `:has-text`, `select_option` options).
- **Occluded left-clicks now land.** When the pre-dispatch hit test finds an unrelated element at the click point, a plain left-click switches to `element.click()` on the resolved target instead of dispatching coordinates into the interceptor — the coordinate path was worse than a no-op (on a drag/pan layer it can start a drag), while the DOM click reaches the target the way assistive tech does. Found live: a workflow editor's accessible button list renders under its SVG diagram, so the resolvable buttons were never coordinate-clickable. The receipt names the path (`clicked via element.click(): … — point occluded by …`; `isTrusted=false`, so an app that requires trusted events will ignore it and the receipt makes that diagnosable). Modified clicks (right/double) keep the coordinate dispatch plus the warning.


## [0.3.0] - 2026-08-20

### Added

- **Vendored Playwright's `InjectedScript` engine** (Apache-2.0, see THIRD_PARTY_LICENSES.md) as `browser/injected_source.py`, built in-repo from a pinned microsoft/playwright commit via `make injected` (node/esbuild at dev time only). Injected lazily once per document into an isolated utility world (main world on the few targets that refuse one; a loud `EngineUnavailable` if neither injects), re-instantiated automatically across navigation and reattach.
- **Strict selector resolution.** A selector matching more than one element with no single visible winner now errors with a candidate digest (preview + generated selector for up to 10 candidates) instead of silently picking the first — wrong-element clicks become impossible rather than diagnosable. A lone match is still used visible or not, and a hidden-vs-visible pair still resolves to the visible one, now announced in the receipt (`[2 matches, 1 visible]`).
- **Click/type receipts.** `Tab.click`/`tap`/`type_text`/`select_option` return a `Receipt` naming what the action actually hit (`clicked: <button id="save">Save</button> — #save (412,133)`), with a warning when an overlay intercepts the point — surfaced as the first line of the `browser_click`/`browser_type`/`browser_select` observation.
- **Actionability waits.** Input methods wait (2 s budget) for the element to be visible, enabled and stable (rAF-based, Playwright's `checkElementStates`) before dispatching; failures name the missing state.
- **Widget-aware typing.** `type_text` verifies the value landed; when keystrokes changed nothing (a framework-controlled input reverting them), it falls back to the native prototype value setter + bubbled `input`/`change` events — React's `_valueTracker` can't see the write across worlds — and re-verifies.
- **`Tab.select_option(selector, option)` + `browser_select` tool.** Native `<select>` (option by label else value, set via the prototype setter) or custom listbox (click field → wait for `role=option` → click it); a miss lists the visible options' accessible names.
- **`aria-ref=` selectors + aria snapshots.** `browser_tree` / `tab.tree()` default to Playwright's `ariaSnapshot({mode:'ai'})` — an LLM-oriented snapshot whose `[ref=eN]` handles are directly clickable as `aria-ref=eN` until the next snapshot, navigation, or reattach (a dead ref errors with a fresh-snapshot hint). `mode="ax"` keeps the raw CDP accessibility tree.
- Real W3C accessible-name matching: `role=X[name=]` and `label=` now use the engine's accname algorithm (labels, alt text, `aria-labelledby`) instead of textContent/aria-label approximations; every selector form pierces open shadow roots through the engine's own css/role/text engines.
- **MCP 2025-06-18** with proper version negotiation: a supported requested version is echoed back (previously the server always answered its own, telling newer clients less than it supports and older clients to disconnect). Additive protocol features: **tool annotations** (`readOnlyHint` on every query tool, `openWorldHint` on everything driving the live web, `destructiveHint`/`idempotentHint` where they apply), **structured tool output** (`get_task` declares an `outputSchema` and returns `structuredContent`; gist tools returning dicts carry them as `structuredContent` alongside the text), `resources/templates/list` advertises `repld://gists/{name}` (was hardcoded empty), and a real `ping` handler — answered by the bridge itself on cold sessions, so a liveness probe costs no kernel.

### Changed

- **Selector resolution is engine-only — the legacy first-visible-pick path is removed** (`_PICK_FN`, `_DEEP_QSA_FN`, and the custom-form JS builders in `selector.py` are gone; `selector.py` is now a pure translation layer). Legacy custom selectors already required `Runtime.evaluate`, so pages the engine can't serve were already unserved; the escape hatches on such pages are `tab.js()` and coordinate `click(x, y)`.
- `Tab.click`/`tap`/`type_text` return a `Receipt` (previously `None`).
- `browser_tree`'s default output is the aria snapshot; pass `mode="ax"` for the previous tree format.
- `text=` matching is exact on normalized text (with an exact `aria-label` retry); former shortest-text tie-breaks among multiple visible matches now surface as strict-violation errors whose digest makes the fix a copy-paste.

## [0.2.9] - 2026-08-11

### Added

- **`Tab.pin(guard_unload=True)`.** `False` skips installing the `beforeunload` guard. The guard fires on ANY unload, same-origin included — found live: a pinned tab driven against a Vite dev server wedged mid-loop (`Page.navigate`/`Runtime.evaluate` both timing out at 30s) because the framework's own HMR full-page reload got stuck behind the guard's native "Leave site?" confirm dialog, which no CDP driver can dismiss. Indistinguishable from a genuinely hung tab from the caller's side. Existing callers are unaffected — defaults to the prior always-on behavior.

### Fixed

- **`Tab.key("Enter")` / `key("Space")` didn't trigger native button/form activation.** `Input.dispatchKeyEvent` without `text` fires the DOM keydown/keyup but Chromium never runs the default action for a focused `<button>` — no click, no form submit. Indistinguishable from the key doing nothing. Now sends `text: "\r"` / `text: " "` for those two, matching a real keyboard; every other named key (`"Escape"`, `"Tab"`, `"ArrowDown"`, ...) is unaffected since it has no native default action. `"Space"` is also now accepted directly (previously only its real `KeyboardEvent.key` value, `" "`, would have worked at all). Also affects `type_text(..., press_enter=True)`, which calls `key("Enter")` internally.


## [0.2.8] - 2026-08-10

### Added

- **`Tab.close()`.** Closes the tab (`Target.closeTarget`); session cleanup follows from the resulting `Target.targetDestroyed` event, same as a user closing it. Previously the only escape hatch was `tab.cdp("Target.closeTarget", targetId=...)` with the raw 32-char Chrome target ID, not `tab.target_id`'s short form and not exposed publicly.

### Fixed

- **Selector resolution had no shadow-DOM fallback.** `text=`, `role=`, `label=`, and `:has-text` all built their candidate list via `document.querySelectorAll`, which never descends into a shadow root — so any selector against a web-component-heavy app (Chrome's own `chrome://extensions`/`chrome://settings` among them, built entirely in Lit/Polymer) silently matched nothing. `selector.py`'s candidate builders now run a shadow-piercing `querySelectorAll` (recurses through `el.shadowRoot`) instead; plain CSS selectors are unaffected — they still resolve via `DOM.querySelector`'s CDP fast path. `label=`'s `for=` resolution now also reads `lbl.getRootNode().getElementById(...)` instead of `document.getElementById(...)`, so a label/control pair inside the same shadow root still resolves.


## [0.2.7] - 2026-08-10

### Added

- **`repld gist add` warns when a linked file imports `repld` at module level.** That makes the whole file kernel-only — importable only inside a repld kernel, never standalone or from a plain script — and nothing said so before: `gist lint`'s `deps` rule exempts `import repld` the same way it exempts stdlib, so there was no signal anywhere until a linked file surprised its new project. Informational only; doesn't refuse the link.

### Changed

- `GUIDE`'s Conventions section and the `gists` help topic now note the module-level-`import repld` caveat directly, instead of leaving it implicit in `repld://docs/production`'s graduation-only framing.

### Fixed

## [0.2.5] - 2026-08-09

### Fixed

- **`repld://gists/_registry` suggested `repld gist add <name>` for a name already resolvable in the current project.** The resource rendered a blanket "link one into the current project" line for every entry regardless of whether that name was already local, global, or linked — unlike `repld gist list`'s `linkable` section, which already excludes those. ## [0.2.4] - 2026-08-09

### Added

- **`repld bridge --ephemeral`** — a private, single-use kernel that spawns eagerly (before the first MCP message, not on first real tool call) and is killed, with its whole state directory reclaimed, the moment stdin closes. Runs in the same cwd as a normal bridge (`./gists`, `repld_init.py`, `.env`, `.venv` binding all resolve identically) but at a socket path outside `PROJECTS_DIR`, so it never attaches to — or is attached to by — anything else. Mutually exclusive with `--socket`.
- **`get_task`'s `result` field** — a deferred task's awaited return value, previously thrown away outright, is now recoverable as a bounded repr after the fact (`defer()` has no cell number to bind `_`/`_N` to instead). The value also prints into the spill/task_done push the same way an exec cell's trailing expression does; `no_display()` suppresses the print but not the `get_task` recovery.
- **The boot sweep reclaims a dead kernel's whole `PROJECTS_DIR/<slug>/` directory**, not just the flat `{pid}-*` files one level down that `sweep_dead_pid_files` already covered. A SIGKILLed kernel used to leave its socket/lock/flock/dashboard/events/cache set behind forever; `state.sweep_dead_project_dirs` reclaims it at the next boot, the same way and with the same conservatism (only a directory whose `kernel.lock` names a dead pid — never one with no lock at all, which may be another kernel mid-boot).


## [0.2.3] - 2026-08-08

### Added

- **`tab.front()`** — brings a tab's window to the front (`Page.bringToFront`), for scripts that want to raise a tab explicitly.

### Fixed

- **`click`/`tap`/`type_text`/`key`/`swipe` silently did nothing on a backgrounded tab.** All five ride `Input.dispatch*Event`, which Chrome drops for a tab whose renderer is occluded or backgrounded (`document.visibilityState === "hidden"`) — the CDP command still acks, nothing raises, and no handler on the page fires. Selector resolution isn't affected (`DOM.getContentQuads`/`querySelector` work fine hidden), which is exactly what made it read as "click did nothing" rather than an error — the multi-window watch workflow this kernel exists for means N-1 tabs are hidden at any given time, so every coordinate/key input against a background tab was a coin flip that reported success either way. All five now check visibility first and call `Page.bringToFront` when hidden — one extra round trip always, the raise only on the degraded path.


## [0.2.2] - 2026-08-08

### Changed

- **`defer()` accepts a zero-arg callable as well as a coroutine** — `defer(lambda: asyncio.gather(one(), two()))` — for constructs that need a running loop to *build*, not just to await. A sync cell (no top-level `await`) runs its body in a worker thread to keep the kernel's loop responsive, so `asyncio.gather()`/`create_task()`/`ensure_future()` called eagerly as a `defer()` argument had no loop to attach to and raised before `defer()` was ever entered. The callable form defers the call itself onto the kernel's loop, inside the scheduled task. Forgetting the parens on an async function (`defer(my_fn)`) is still the same friendly, synchronous `TypeError` naming the function — only a genuine zero-arg callable (a `lambda`, a plain function) is treated as a factory.

### Fixed

- **The "no current event loop" hint pointed at `defer()` even when the cell was already using it.** The RuntimeError comes from building `asyncio.gather()`/`create_task()`/`ensure_future()` in a background thread — a sync cell has no top-level `await` and so runs off the kernel's loop — and the old hint text said "use defer() to schedule async work" regardless of whether `defer()` was the very call that failed. It now explains that these need a loop at *construction*, not just to await, and points at wrapping the call in an `async def` or, if deferring it, passing `defer()` a zero-arg callable (see Changed).


## [0.2.1] - 2026-08-06

### Added

- **`repld help migration`** — why a project has no `.pyrepl.*`, `.mcp.json`, `CLAUDE.md` block or `repl.py` any more, where each moved to, and what a `.pyrepl.*` you *do* find means (0.1.x leftover; the lockfile may name a live pid, the dashboard hint holds a dead API token). It answers a question about absence, which is the one an agent hits and the one no API reference covers. A topic rather than a `repld://docs/*` resource deliberately: a doc resource is permanent surface advertised in every session, and this expires with 0.1.x.

### Fixed

- **Binding a kernel to the project venv no longer takes the browser extra away.** `bind.rebind_exec` re-execs under `uv run --with-editable <repld>`, and `uv run` builds a fresh environment from the spec it is handed — the interpreter being left behind contributes nothing to it. So a repld installed *with* `[browser]` re-execed into an environment that had none of `duckdb`, `websockets` or `pillow`, and the kernel came up with no `browser` builtin and no browser MCP tools. The rebind now carries the extra when the process it is replacing already had it (`bind.has_browser_extra`), which is a rule about not *losing* a capability — a repld installed without the extra still doesn't resolve duckdb by itself. The tell was that browser worked in every project *without* a `./.venv` and in none of the projects with one, since only the latter rebind at all.
- **A missing browser dependency says which one.** `kernel._inject_builtins` caught the `ImportError` and passed, so the failure surfaced much later and somewhere else — `NameError: name 'browser' is not defined` in a cell, or 21 tools simply absent from `tools/list`. Both read as "this kernel has no browser" and neither said why, which sends the reader to the browser stack instead of to the environment. It now names the module it couldn't import, which is the only thing at that point that knows.


## [0.2.0] - 2026-08-05

### Upgrading from 0.1.x

Four things to do, none of which repld can do for you. There is a prompt to paste into your agent, and the same list by hand, at <https://angelsen.github.io/repld/docs/guides/upgrading/>.

1. **Clean up `.pyrepl.*`.** A 0.1.x kernel writes `.pyrepl.lock` and `.pyrepl.sock` into the project and removes them on a clean exit; `.pyrepl.dashboard` it never removes. A surviving lockfile may mean a kernel is still running that 0.2 can't see — confirm its pid with `ps -p <pid> -o pid,command` before signalling, since a stale one can name a reused pid. Then `rm -f .pyrepl.lock .pyrepl.sock .pyrepl.dashboard` and drop the `# repld runtime state` block from `.gitignore`. Check `git ls-files | grep '^\.pyrepl\.'` first: `.pyrepl.dashboard` holds that kernel's dashboard API token and was only gitignored where `repld init` ran.
2. **Re-register the MCP server:** `claude mcp add repld -- repld bridge`. Then delete the project's `.mcp.json` (and the matching `"repld"` in `enabledMcpjsonServers` in `.claude/settings.local.json`) and the `<!-- repld:start -->` block from its `CLAUDE.md`. The generated entry ran `uv run repld bridge` wherever a `uv.lock` existed, which now costs a `uv sync` per session for an interpreter repld picks itself.
3. **Rename your bootstrap:** `mv repl.py repld_init.py`, and drop `--init` from any launch command. The file is found by name now, on every kernel — including the ones you don't start yourself.
4. **Migrate any gist still declaring `__repld_tools__`** — it is now ignored rather than warned about, so the file quietly loses its tools. Give each argument its own typed parameter on a `_tool_*` function, move the tool description to the docstring's first line, and put per-parameter descriptions in `Annotated[T, "..."]`. `repld gist lint` is the only thing that will tell you.

Three more, if they apply to you:

- **If your system has no `XDG_RUNTIME_DIR`** (macOS, most containers, any env-scrubbed spawn): the fallback root moved from `/tmp/repld` to `/tmp/repld-{uid}`, uid-suffixed so it can't be pre-created and owned by someone else. Nothing reads the old one again — `rm -rf /tmp/repld` once the last 0.1.x kernel is stopped.
- **If you only ever run headless kernels:** gist dependencies now need one deliberate install, because a kernel with nobody watching no longer answers its own consent prompt. Start `repld` in a pane once to be prompted, or run the `uv pip install --target …` command it prints.
- **If you bookmarked a dashboard URL:** it will answer 401 now. The page carries an API token, so it is no longer served without one — open it with `repld dashboard` (or `repld dashboard --print` for the URL), which supplies the token from the kernel's private state file. Ephemeral ports meant bookmarks never survived a restart anyway.

`repld[browser]` now requires Chrome 140+.

### Added

- **Lazy kernel spawn.** Opening a Claude Code session no longer spawns a kernel by itself: MCP discovery is answered from a per-project `kernel.cache` (or a static fallback in a cold project), and only a real `tools/call` or a gist/browser `resources/read` triggers a spawn. A kernel that is already running is still attached to for free.
- **Headless kernel.** `repld bridge` spawns a detached kernel on demand, so starting `repld` by hand is now optional — do that when you want the live TUI display. The kernel persists until explicitly stopped, so in-memory state survives a Claude Code restart.
- **Self-healing bridge.** If the kernel dies mid-session the bridge answers each orphaned request with `-31001`, then respawns and replays the client's cached handshake so tools and channel pushes keep working. Liveness is probed before forwarding, never by retrying — `exec` runs arbitrary code and must never run twice.
- **One kernel per project, enforced by flock.** A second `repld` in the same project prints a note and exits 0, so a racing bridge or human connects to the incumbent instead of failing.
- `repld log [-n N] [-f] [--json]` — replay or follow a headless kernel's activity from any terminal, rendered as the TUI renders it. Backed by a new NDJSON event log; `--no-display` mode previously discarded every event.
- `repld status [--json]` — this project's kernel (pid, uptime, socket, dashboard port, active tasks/tickers) plus every live kernel elsewhere, so auto-spawned kernels don't accumulate unseen.
- `repld stop [--all]` / `repld restart` — lifecycle control for kernels you never started.
- `repld dashboard [--print]` — resolve the running kernel's dashboard port and open it, printing the URL when a browser can't be opened.
- `python -m repld` entry point (`src/repld/__main__.py`), which is how the bridge spawns kernels.
- **The kernel runs as its own systemd user service where systemd is available**, so it gets its own cgroup and lifetime rather than being a child of whoever spawned it, and its output reaches the journal (`journalctl --user -u 'repld-<slug>-*'`) — the only place a bridge-spawned kernel's boot failure can be read. Any systemd failure falls back to the previous detached-child path; `REPLD_MEMORY_HIGH` and `REPLD_OOM_SCORE_ADJUST` are opt-in and change nothing by default.
- **The kernel binds itself to the project's virtualenv**, re-execing through `uv run` before boot so code in `exec` can import the project it sits in — which a uv-tool install could not do, its interpreter being fixed by the console script's shebang. This, not a gist declaring `__repld_deps__ = ["."]`, is why a globally-installed repld reaches a project's dependencies.
- **A version-matched venv appearing after boot is adopted live; a mismatched one is refused.** Splicing a mismatched venv half-works — pure-Python and `abi3` packages import, compiled ones don't — so `sys.path` is left alone and the failing import explains why, naming the venv, both Python versions, and `repld_restart`.
- **`repld_restart` MCP tool** — restart the project's kernel from inside the conversation; the MCP session survives, in-memory state deliberately does not. Served by the bridge, since a kernel cannot answer "restart yourself" without the reply dying in flight.
- **`repld_init.py` — a project bootstrap that every kernel runs**, whoever started it, replacing the `--init` flag (see Removed). It runs *after* the socket binds so lazy spawn's 5 s window isn't spent on it, pushes `init_loaded` or `init_error` when it finishes, and never takes the kernel down on failure — a broken bootstrap is exactly when you need a live kernel.
- **Per-parameter descriptions for gist tools, via `Annotated[T, "..."]`.** A typed `_tool_*` function spends its docstring's first line on the *tool* description, leaving nowhere to say a parameter is a date in `YYYY-MM-DD`; bare-string `Annotated` metadata now becomes that property's `description`. Purely additive, and `repld gist new` scaffolds with it.
- **`every(seconds, delay=...)`** holds the first tick back. The default immediate tick is right for polling something that already exists and wrong for watching something you just started, where a false negative at its most fragile moment can send a re-raise loop after something that was about to be fine.
- **`load_dotenv()` is public** — `from repld import load_dotenv`. `./.env` is read once at boot while `./gists` reload on mtime, so a value written afterwards was invisible with no way to ask for it; existing vars still win, so a name captured while empty must be cleared before re-reading.
- **`repld gate` — see and answer the human gates a kernel is blocked on.** Only the TUI's stdin reader and a pinned tab's pill could answer before, and a kernel spawned *for* you has neither, so `confirm()` blocked forever on what lazy spawn made the common case. `repld gate answer <id> <value>` resolves one over the same IPC socket; deliberately not an MCP tool, since an agent answering its own `confirm()` defeats the primitive.
- **The `awaiting_human` channel push now says when nobody can answer it**, carrying the literal `repld gate answer <id> <value>` command — the agent is what reads the push and the human is what needs the command. Gates also carry their id into `repld log -f`.
- **`repld gist fetch <gist-url>`** — download a GitHub gist's `.py` files into `./gists`, or `~/.repld/gists` with `--global`, stamped with a `# source:` header. It is `new`'s sibling rather than `add`'s: a snapshot you then own and edit, where `add` records a link and keeps tracking the file it points at. `--name` renames a single-file gist, `--force` re-fetches over your copy, and the three collision scopes `add` enforces (local, global, already linked) apply here too. Declared `__repld_deps__` are reported but not installed — `add` links code you wrote, this is code from a URL, and the next kernel boot prompts for them anyway.
- `repld gist lint --local` — restrict the check to `./gists`. The default scope spans every gist a kernel here would import, which is right for a manual sweep but makes the exit code useless as a CI gate when a linked gist from another repo fails the run.

### Changed

- **`repld/browser/__init__.py` split into `browser.py`, `pool.py` and `target.py`**, leaving the package `__init__` as re-exports. It was 990 lines holding `Browser`, `BrowserPool` and `LazyBrowser` inline — the one module that never got the treatment `tab.py` had when `tab_query` / `selector` / `row` / `pin` were carved out of it. Every public import path is unchanged, and `make_target` now sits in a leaf module, so `tab.py` and `observe.py` take it at module level instead of a call-time `from . import make_target` to dodge a cycle.
- **Duplicated derivations given owners.** The JSON-RPC envelope builders moved to `core_schemas` (the bridge hand-built them at ten sites and cannot import `protocol`), and the bridge now reads a doc resource's `mimeType` from the same declaration it advertises rather than a literal. The two gist directories are `paths.global_gists_dir()` / `local_gists_dir()` / `gist_dirs()` instead of fourteen hand-written copies, one of which carried a hand-sync comment. `gates.yes_by_default` replaces two private `("", "y", "yes")` sets that accepted less than `gates.parse_response` does, so `1` and `true` declined a boot prompt while confirming a gate.
- The kernel's boot banner advised `claude mcp add -s project`, the scope that writes a `.mcp.json`. It prints the plain local-scope form now.
- **`exec` no longer runs a full garbage collection after every cell** — 164 ms per cell against 800k live objects, in a runtime whose premise is holding large state for weeks. It is a generation-0 collection now (~0.005 ms), which is where an abandoned coroutine actually is.
- `browser.get(id, timeout=…)` now bounds the target-ID path too. It was documented as ignored there, which since the attach-race retry became a proper deadline loop meant a five-second floor on a call asking for one. An ID matching no target still fails immediately either way.
- The browser tool timings that were bare literals are named: `_SETTLE_NAVIGATION_S` / `_SETTLE_INTERACTION_S` / `_SETTLE_DEFAULT_S` in `browser_dispatch`, plus the two unexplained 0.3 s pauses (`_POST_TYPE_DEBOUNCE_S`, `_POST_REATTACH_SETTLE_S`). `cdp._INFLIGHT_MAX_AGE` justified itself against `observe.settle`'s 5 s default, which no caller passes; it now names the real ceiling, the 8 s navigation settle.
- The HAR, console, SSE and lifecycle views no longer end in an `ORDER BY` every caller already overrides — 35.4 ms → 30.4 ms at 40k events on the `har_summary` delta `post_observe` runs per tab per mutation. It was also the thing that made an order-dependent query look correct until its result set outgrew its `LIMIT`, which is exactly how `Tab.sse()` / `Tab.lifecycle()` once returned the *oldest* 500 rows.
- **The IPC socket is created 0600 rather than chmod-ed to it**, closing a window in which it was connectable by any local user. The 0700 project directory was and remains the actual barrier, so this is defence in depth rather than a live hole.
- **Runtime state moved out of the project directory** into `$XDG_RUNTIME_DIR/repld/projects/{basename}-{sha256(realpath)[:8]}/`, created 0700. Every file is the socket path with a different suffix (`.lock` / `.flock` / `.dashboard` / `.events`), so `--socket` and `REPLD_SOCKET` move the whole set together; the `./.pyrepl.*` fallbacks are gone.
- **Channel pushes caused by a specific request now go only to the session that made it**, `defer()` included. Genuinely ambient pushes stay broadcast (`@every` errors, console errors, browser connect/disconnect, bare `notify()`), and a push whose origin disconnected is dropped rather than downgraded to a broadcast that would leak one session's output into every other.
- **A headless kernel no longer builds the display event queue at all.** It was initialized anyway and a drain thread started solely to discard it, costing two lock round-trips and a cross-thread wakeup per event — several per `print()`. No behavioural change: the event log, `repld log`, and channel pushes are fed by the sink, which always ran first.
- The MCP `initialize` response declares `listChanged: true` for tools and resources, a prerequisite for the bridge's post-respawn notifications. `CAPABILITIES` and `PROTOCOL_VERSION` now live in one module, since `initialize` has three authors — kernel, bridge, and `repld exec` — and a drifted capability *disables* a feature rather than degrading it.

### Security

- **`atomic_write_json(chmod=…)` creates its temp file at that mode instead of chmod-ing it afterwards.** The temp briefly sat at 0644 holding byte-for-byte what the final file would — the dashboard's API token, the session registry, the kernel lockfile — which is the exact thing the rule exists to forbid. Every affected file lives under a 0700 directory, so this is defence in depth.
- **A headless kernel no longer installs gist dependencies without being asked.** The `[Y/n]` prompt read a bare Enter as yes, and an auto-spawned kernel has stdin on `/dev/null` where `readline()` returns `""` immediately — so the prompt degraded into unattended consent on what is now the default spawn path, for any reachable gist's `__repld_deps__`. The gate is a genuine tty check now, and a kernel that can't prompt reports what's missing and prints a copy-pasteable install command. **Headless-only users need one deliberate install; at a real terminal nothing changes.**
- **The dashboard's `POST /api` caps its request body at 1 MiB.** `Content-Length` was read unbounded and handed straight to `readexactly()`, so a single header claiming 10 GB had the kernel allocate toward it — and the 5 s read timeout is no defence against a sender on loopback. The cap sits *after* the Bearer check, so an anonymous caller still gets 401 and cannot probe for the limit. Holding the token is not licence to OOM the process the token exists to protect.
- **Runtime state is no longer world-readable when `XDG_RUNTIME_DIR` is unset** — macOS, most containers, any env-scrubbed spawn. `Path.mkdir(mode=0o700)` applies the mode only to the leaf, so `/tmp/repld` came out 0755 and task spills, screenshots, and the session registry were created 0644; the fallback root is `/tmp/repld-{uid}` now, created 0700 and refusing a root another user owns. **Delete the old `/tmp/repld` once the last 0.1.x kernel is stopped** — see Upgrading above.

### Fixed

- **The dashboard's API token gated nothing.** `GET /` served the control panel — with the token embedded, since the page needs it — to anyone who asked, so any process on the machine could take it, enumerate every project cwd via `sessions`, and reach your Chrome through the browser RPCs. It requires the token now, as `?token=` or a per-port cookie; `POST /api` stays Bearer-only. **Open it with `repld dashboard`; a bare `http://127.0.0.1:<port>/` answers 401.**
- **The dashboard read an unbounded number of request headers before any authentication** — one connection was measured feeding 200,000 in without the server answering. Capped at 100 lines with a 431.
- The dashboard page's `esc()` escaped `& < >` but never quotes, and it is used in attribute position throughout with tab URLs, page titles and project paths. Responses also declare `Connection: close` now, which is what the server always did.
- **Every observed browser mutation stalled the kernel loop with DuckDB queries, before and after** — 22–82 ms per tab plus once per iframe on the way in, another 39–56 ms on the way out. Worst-case stall drops from 104 ms to 7 ms.
- **The dashboard's Console and Network tabs ran their scans on the kernel's shared loop**, stalling every cell, ticker and observation for the length of the scan. The panel also fetched its kernel state exactly once, so uptime, tasks and tickers sat frozen at page-load values.
- **One SSE connection permanently wedged `settle` on its tab.** A request left the in-flight set only on `loadingFinished`/`loadingFailed`, which a stream emits only when it closes, so every later mutation burned its full deadline. Streamed responses clear when their headers arrive; anything still open after 60 s is aged out.
- **Fire-and-forget async work could be garbage-collected mid-flight.** `asyncio` holds only a weak reference to a running task, so ten `create_task` calls whose handles nothing kept could vanish — the worst being the `Fetch.requestPaused` handler, the only thing that resumes a paused request, whose loss hangs it in Chrome with `settle` waiting. Also reachable: a tab attaching but recording nothing, `watch()` skipping a tab, and a gate rendering no pill. `bg.spawn` holds the reference.
- **A failed event-store insert could hang a paused request.** `CDPSession._handle_event` stored the event before dispatching `Fetch.requestPaused` and `Runtime.bindingCalled` under one `except Exception: logger.debug(...)`, so a raise from the store skipped both — wedging the request and swallowing a gate answer, at debug level. The store is guarded on its own now.
- **A long-lived kernel never reclaimed its own scratch.** Spill eviction walks the task registry and the boot sweep only collects what a *dead* pid left, so a live kernel's spills, oversized tool responses and screenshots accumulated for its whole life. Both classes age out at one hour now. **A path handed to the agent, `[full output: …]` included, stays readable for roughly an hour.**
- **Per-process scratch left by dead kernels is now swept at boot** — thousands of files otherwise, permanently so under the `/tmp` fallback.
- **A hung dependency install could wedge the whole kernel** — `install_deps()` ran with no timeout, and two of its three call sites are in the gist import hook, i.e. on the shared loop. Capped at 10 minutes, printing the command to run by hand.
- **A gist declaring a new dependency mid-session could wedge the kernel.** The consent prompt is correct at boot and nowhere else: past that, the display thread is parked in `readline()` on the same stdin, so the prompt waits behind a reader that discards the answer — and on an `await` cell that is the whole loop, with no await point for the watchdog's cancel to land on. `tty_prompt` declines once the display claims stdin.
- **The pane's stdin claim was never released**, so after an EOF on a redirected stdin `tty_prompt` declined for the rest of the process's life and blamed a thread that had exited.
- **A cell that finished in the wrong millisecond was promised a completion push nobody sent.** `exec` marked a task nudged *after* snapshotting its output; a cell completing in that window had its push dropped while the reply said one was coming. The promise is taken atomically now, and `exec` answers with the result when it couldn't be.
- **An `@every` ticker's output was attributed to the cell that registered it, and then thrown away.** The ticker inherited that cell's task id and kept it for the life of the kernel, so its `print()` filled a *finished* cell's 4 KB budget and was dropped permanently by both the display and `repld log` — the only surface a headless kernel has. Tick output is ambient now, unattributed and uncapped.
- **An `@every` cancelled during its inter-tick sleep stayed in the registry forever**, so `every.list()` and the dashboard kept reporting a schedule that no longer existed.
- **The loop watchdog cancelled an arbitrary task while reporting it as the longest-running one** — its fallback sorted `Task-N` lexicographically, so `Task-10` came before `Task-2`. It also reported a kill it hadn't performed, since it cancels via a callback on the loop it just declared wedged; it reports the cancellation as *requested* now.
- **`get_task` could answer `-32603` for a task whose spill had just been evicted**, reading the file unguarded where its sibling had always caught this.
- **A request could hang forever if the kernel died at exactly the wrong moment** — the socket could go to `None` between the liveness probe and the write, leaving the id registered with nothing to answer it. It takes the same orphan path a failed send does.
- **A stale bridge reader could tear down a freshly attached kernel**, nulling the replacement's socket and answering every id against it with `-31001`. The generation check happens inside the teardown now, under its lock.
- **One unexpected exception in the bridge ended the MCP session.** Anything outside `BrokenPipeError`/`OSError`/`ValueError` — a malformed `kernel.cache` sufficed — fell out of the stdin loop and closed the bridge's own stdout, which an MCP client can never recover from. It answers `-32603` like the kernel end always has.
- **A failing kernel respawn could print its explanation fifty times**: `quiet=True` stopped at the bridge's own stderr, while every line saying *why* lives in `spawn.py`. The same poll re-ran a full `systemd-run` spawn every 100 ms; it retries every 500 ms, as the code already claimed.
- **A standard MCP `ping`, or one malformed stdin line, spawned a kernel** — anything the discovery intercept didn't recognise fell through to spawn-and-wait, defeating lazy spawn for methods no kernel implements.
- **A cold-start MCP session was told nothing about gists.** With no kernel and no cache the bridge served `initialize` with the exec model alone — no `./gists`, no `_tool_*`, no `__repld_deps__` — and nothing re-sends `instructions` after the lazy spawn. The same drift left `repld://gists/_registry` out of a cold `resources/list`.
- **The first `exec` after a lazy spawn could race the project bootstrap**, reaching a bare `__main__`; so could a gist or browser tool, which is the *other* thing that spawns one. Both wait for the bootstrap now, released unconditionally however it went, since a kernel nobody can run code in cannot be repaired.
- **A browser or gist tool that outran its 30 s deadline reported an error with no message** — `concurrent.futures.TimeoutError` *is* `TimeoutError` and carries an empty string. The deadline is named, along with the fact that the call was abandoned rather than cancelled.
- **`repld_restart` could reattach to the kernel it had just killed** and report it as the replacement, since a kernel draining `@every` and `defer()` blocks keeps its pid and socket past the wait budget.
- **A dead-but-unreaped kernel counted as running.** `os.kill(pid, 0)` succeeds for a zombie, and repld makes those routinely — so `repld stop` reported "did not exit within 10s" about a process that had exited, and stale lockfiles were blessed.
- **One unreadable session file could take down `repld status` and `repld stop --all`**, which returned an unparseable payload every consumer indexes `pid` on. `stop --all` also aborted its whole sweep on a session file lacking `socket_path`.
- **A kernel that failed to start printed nothing at all** — an over-long `--socket` path, a permissions problem and an already-bound port all presented as a bare non-zero exit. Boot writes the failure and traceback to the real stderr now.
- `state.acquire_lock` could bring `RUNTIME_DIR` into being as an implicit parent at 0755 under `--socket`/`REPLD_SOCKET`, skipping the mode and foreign-owner check.
- `kernel.flock` could hold a mangled pid, being deliberately never truncated (`99` over `123456` reads as `99456`). Nothing reads it — it exists to be looked at — so it is truncated before the write.
- `ipc.connect_to_kernel` dropped its socket unclosed on a failed connect — 50 per bridge respawn, each with a `ResourceWarning`.
- **Human gates could be left unanswerable.** A gate that timed out (or whose cell was cancelled) resolved nothing, so the pane's entry stayed, stayed newest, and the stdin reader routes to the newest — every line typed afterwards silently answered a gate the kernel had already dropped. The pane also tracked a single open gate where `gates` allows several, so answering an older one stranded the one on screen. Both now emit `HumanPromptClosed`, rendered as `↳ no response (timeout | cancelled)`.
- **`choose()` answered by number returned the number**, not the option. Coercion lives in one place now, shared by the pane and `repld gate answer`.
- **A second open gate re-prompted with placeholder text** — `? still waiting [y/n] #a1b2c3` — where the pane is the only thing telling the human what is being asked.
- **`tab.ask()` on a pinned tab was a gate nothing could answer.** The pill has buttons and no text input, so it draws nothing for an `ask` — but routing was decided on pinnedness alone, which also suppressed the `repld gate answer` command the push carries when no other surface exists.
- **`repld gate answer` mangled an answer that looked like one of its own flags.** Every parser reached past the gate id, so `repld gate answer <id> deploy --socket now` answered `"deploy now"` with the connection silently repointed at a kernel called `now`. Everything after the gate id is the answer verbatim; flags go before `answer`.
- **Adopting a late-appearing venv sent a malformed channel push** — `push_kind(content, kind)` called with its arguments swapped, which type-checked, linted and ran since both are `str`. A call-site sweep now runs in phase 4.
- **`bind.rebind_exec` could raise despite documenting that it can't** — a corrupt `direct_url.json` killed the MCP server at startup rather than degrading to an unbound kernel.
- `repld status` could warn about a virtualenv belonging to neither party, `project_venv()`'s `$VIRTUAL_ENV` fallback having ignored the cwd it was given.
- `repld restart` reported failure while a healthy kernel was coming up: `spawn_headless` returned `False` both for a failed spawn and for a racing boot that already owned the unit.
- **`repld exec` is no longer slowed by the venv bind** (~336 ms → ~82 ms) — the code it runs executes in the kernel, which is already bound.
- `repld exec` exited 0 printing nothing when `get_task` returned an error, and exited 1 with an empty stderr if the kernel died while fetching a finished task's output — the one moment where silence costs you the result. Its interactive banner also omitted `no_display`, the builtin whose whole purpose is to be discovered at the REPL.
- **`repld log` printed cell output one *chunk* per line** instead of one line per line, a single `print("a", b)` arriving as four chunks. It could also drop a truncated cell's elision notice when output filled the cap exactly on a chunk boundary, so the cell appeared complete with nothing saying otherwise.
- `repld log -n 0` printed the entire log and `-n -5` everything but the oldest five; `--json` emitted a non-JSON line into the stream, breaking `| jq` precisely when no kernel was running.
- **`repld log` and the live TUI render the same events identically again** — the human-gate response, the tab title on attach lines, and a channel push leaving colour switched on had all drifted.
- **`repld status` could crash on a malformed dashboard hint file**, and printed dashboard URLs that answer 401 now that `GET /` is authenticated. `repld dashboard` also left the API token in shell scrollback on the success path; it reports the port instead.
- **The dashboard hint file was only ever written by browser code**, so on a kernel that never touched the browser `repld status` couldn't authenticate and the dashboard drew a fresh random port on every restart. It is written as soon as the server binds, and merges rather than replaces.
- `repld help`'s state check stat'd `./.pyrepl.lock` and advised deleting a stale one by hand — a file that no longer exists, and advice the flock mutex made wrong anyway.
- **`repld bridge` accepted any argv at all** — `--help` started a proxy blocking on stdin, and a typo'd flag in an MCP registration was silently ignored, on the one command with no terminal to notice.
- **The `repld gist` verbs disagreed about unknown arguments.** Only `fetch` and `list` validated, so `gist new x --global` scaffolded locally while ignoring the flag its sibling honours, `gist add foo bar` linked only `foo`, and `gist lint --json` went looking for a gist named `--json`. `--help` was checked on the first argument alone, so `repld gist rm foo --help` unlinked `foo`, and `repld help gists --help` printed the topic. Four of six verbs also kept private copies of a usage string the command table owns. All of it goes through `cli_args` now.
- **`repld gist new` could silently shadow a gist you had linked from another project**, replacing working code with a stub; **`repld gist add` could silently repoint a name another linked gist depends on**, reported as nothing more than `+ siblings: <name>`. All three commands enforce the same three collision scopes.
- `repld gist list` reported a corrupt `./gists/.links` and still exited 0, printing a listing that silently omitted every linked gist; `repld gist fetch` tracebacked on the same file.
- **`repld gist lint` created `./gists` and `~/.repld/gists` in a project that had neither**, then reported "no gists found". It refused a `--local` name whenever a global gist shared the stem, tracebacked on a single non-UTF-8 file, and reported three things that were not wrong — the soft-dependency idiom, and import roots compared against *distribution* names, so a gist declaring `pillow` was told it hadn't declared `PIL`.
- **A wrong-shaped gist registry crashed `repld gist list`, `link_targets` and the `_registry` resource.** Non-dict roots and non-UTF-8 files read as empty now.
- **Private gists were skipped by dependency scanning and by lint, but only when local** — so a private helper's `__repld_deps__` was never scanned and the sibling importing it died on a bare `ModuleNotFoundError`.
- **`__repld_deps__ = ["."]` installed a dependency the kernel could never import** — an editable install lands in the target dir as nothing but a `.pth`, which `sys.path.append` never processes. It uses `site.addsitedir` now.
- **Gist dependencies now install somewhere durable, stay visible to a bound kernel, and work under a system Python.** They went into whichever venv was active, gated on a `sys.prefix` test that binding made false, so accumulated deps became invisible and fresh installs landed in an ephemeral overlay — returning the prompt forever. **The loose files directly under `~/.local/share/repld/deps/` are unused now** and can be deleted by hand.
- **A gist using `from __future__ import annotations` got a wrong tool schema** — under PEP 563 every annotation reaches `inspect.signature` as a string, so `int` stopped mapping to `integer` and `Annotated[T, "..."]` was invisible, silently typing every parameter `string`.
- **`tab.label` never survived a navigation, which is the only reason it exists.** The registration runs at document *start*, where `document.body` is still null, so the mount threw — and `runImmediately` masked it by also evaluating against the loaded document, so the bar appeared when you set it and never came back.
- **The label bar and the gate pill both stopped working after a browser reconnect.** Both are session-scoped registrations, and both restores lived outside `_reattach_core` — so a WebSocket reconnect (sleep, network blip, Chrome restart) dropped them while a *navigation*-triggered reattach recovered. The pill's buttons then called an undefined function, having already cleared the gate from their own queue: a gate that could not be answered from the surface showing it.
- **`tab.unpin()` could strand a tab pinned forever**, cancelling the heartbeat before removing the pill, so a raise left `_pinned` set with nothing left to clear it.
- **`since=` meant three different clocks across four methods on the same object** — epoch seconds, epoch *milliseconds*, and a monotonic counter from an arbitrary origin. So `tab.console(since=time.time())` returned everything rather than nothing, and the two monotonic ones returned nothing. It is epoch seconds everywhere now — pass `time.time()`.
- **URL filters over-matched on `_` and `%`**, LIKE's own metacharacters being left live, so `/api/user_profile` also matched `/api/userXprofile`.
- **Selectors disagreed about whether a hidden element counts** — `text=` was the only form considering visibility, so `text=Save` skipped a hidden button while `role=button[name="Save"]` returned it and the click landed on nothing. All four forms rank visible matches above hidden ones.
- **`ready="main"`, or any bare tag or custom element, silently never matched** — it took the JS branch, came back a ReferenceError, and polled for the full 10 s, while `ready="#app"` worked. Classification is shared with `click`/`type_text` now, so `text=`, `role=`, `label=` and `:has-text()` work here too.
- **A redirect chain reported the wrong status on its final hop** — a 302 → 200 login showed as `302` with `state: complete` beside it, hops having been collapsed with `MAX(...)` over a VARCHAR status. The same collapse could show hop 1's `Cookie` on hop 2. Both are numbered per hop and joined on `redirect_index` now.
- **`tab.request()` dropped five fields it was documented to return** — `curl_command`, `auth_cookies`, `request_cookies`, `loader_id` and `frame_id`, the first of them — the headline reason the column exists — leaving it reachable only by hand-written SQL. **`curl_command` also silently corrupted any body containing an apostrophe**, producing not a broken command but one that still ran, having quietly dropped the apostrophe and everything quoted around it.
- **`tab.control_observations()` always returned an empty list**, parsing a payload the `console_entries` view never exposes; **`browser_invoke` never returned the control's result**, discarding the one thing the tool exists for while its description advertised the shape. It returns `{result, observation}` now.
- **`tab.screenshot(full_page=True)` returned a squashed image and dimensions describing something else** — measured from the visual viewport while `captureBeyondViewport` captures the whole content box.
- **Captured response bodies never counted toward the event store's FIFO cap** — the rows that dominate its memory, at up to 500 KB each, were the only ones invisible to the prune trigger.
- **Every asset body on a captured tab made a needless round trip through CDP.** Interception must register on `*`, and the handler skipped only redirects and SSE — so every image, font, stylesheet and script had its body pulled over the debug socket and pushed straight back, a round trip plus ~2.7× the resource's bytes, for rows `tab.network()` hides by default. Assets are skipped up front; `tab.body()` still fetches one on demand.
- **A failed `Fetch.disable` was reported as success**, clearing the handler while Chrome was still intercepting — which hangs every subsequent request on that tab.
- **`tab.capture_bodies = True` immediately followed by `= False` could settle inconsistently**, the setter being fire-and-forget. Serialized per session, by a wrapper rather than the body, since `Fetch.enable` can trip a reconnect that re-enters on the same task.
- **Closing a tab mid-query surfaced as `browser_network: Connection Error`** — `cleanup()` closed the DuckDB from the loop while the query methods take per-call cursors precisely so they can run off it. The close waits out an in-flight read now.
- **A failed reconnect leaked every tab's event store, and a partly-failed one left a live session with a closed one.** `BrowserSession.disconnect()` leaked them too, closing the WebSocket while leaving each tab's DuckDB open — and since reconnect replaces the whole `Browser`, nothing ever came back for them.
- **A cleanly closed Chrome socket stalled every in-flight CDP command for 30 s and skipped auto-reconnect.** `websockets` swallows `ConnectionClosedOK`, so on a polite close nothing failed the pending futures, each caller waited out its `wait_for`, and `TimeoutError` is deliberately not recoverable — so the retry an *abrupt* close gets for free never ran. The tidier failure was the worse one.
- **Concurrent browser connects each opened their own WebSocket**, N callers producing N sockets and N recv loops with only the last reachable — the rest left open against Chrome for the life of the kernel. Two parallel tool calls on a cold pool is enough.
- **`BrowserPool`'s multi-browser fan-out could die on "dictionary changed size during iteration"** — five methods iterate `_browsers` with an `await` in the body, and a dashboard Connect click landing during a `watch()` sweep was enough. `disconnect` also removes snapshotted ports one by one rather than `clear()`, which would drop a browser connected mid-sweep with a live WebSocket nothing would close.
- **Two browser tools walked loop-owned state from a foreign thread.** `browser_tabs` and `browser_clear` weren't routed through `_run_async`, so one popup mid-call killed the tool; `browser_clear` also reset `_event_count` and `_inflight` off-loop, racing `store_event`'s `+=` and leaving the prune trigger describing a store it no longer matched. Routing the tool was half of it — `browser.clear()` in a pure-sync cell and the dashboard's own call reach the same code from their own threads — so the counter resets are scheduled onto the loop whoever calls. The sync browser API also snapshots those maps before walking them, since every pure-sync cell already runs off-loop.
- **Off-loop fire-and-forget work waited on the watchdog to run at all.** `bg.spawn(loop=)` used `loop.create_task`, which from a foreign thread queues the first step without waking the loop — so on an idle loop the coroutine never ran, and what made it look fine was the watchdog's once-a-second probe draining the queue.
- **`browser.get("9222:abc123")` on a cold pool failed** with "No browser on port 9222", the target-ID path having skipped the auto-connect the glob path does.
- **A glob `browser.get()` and `browser.open()` both failed on a tab they were about to attach** — when a target matches a watch pattern, repld's own auto-attach claims it first and `attach()` answers `None`, which both read as a miss. They wait the race out now, bounded by the caller's timeout.
- **An iframe observation reported unrelated tabs' modals as its parent's**, having evaluated JS in every attached page-type target at one round trip each. It resolves the real parent through `parentFrameId`.
- **`repld://docs/guide` told agents that a globally-installed repld cannot see project dependencies.** It can, and has since the kernel started binding itself to the project's interpreter — the same document's setup section recommends exactly that install.
- **The browser guide showed `browser.pages()`, `.detach()` and `.disconnect()` without `await`**, in a block that awaited the adjacent calls correctly. All three are coroutines; as written they did nothing.
- Documentation corrections: the settle loop was still documented as a DuckDB query; `repld help gists` said dependencies install into the venv (they go to a shared, interpreter-versioned dir, and deliberately never the venv); the channel-kinds table listed a `user` kind nothing emits while omitting `venv`.

### Removed

- **`repld init` is gone, and repld no longer writes anything into a project.** Both files it wrote were snapshots of advice frozen at the moment it ran, and the `.mcp.json` proved the point by drifting when `bind.rebind_exec` moved binding inside repld — leaving every earlier project on `uv run repld bridge`, paying a per-session `uv sync` to reach the same interpreter. The CLAUDE.md block was redundant besides: every claim in it is already in the MCP `initialize` instructions, which are always loaded and always current. See Upgrading above.
- **`repld --init FILE` is gone, replaced by an auto-detected `repld_init.py`.** The flag only ever fired for a human starting the kernel by hand *and* winning the flock, and `spawn._kernel_argv` records no init path — so a project whose kernel *hosts* something lost its entire bootstrap, silently, the moment a lazy spawn or restart replaced it. Both failure modes are gone rather than fixed, there being no per-invocation flag left to drop.
- **The `__repld_tools__` tool-registration list is gone**, a release earlier than planned: a scan of every registered gist found three users, all migrated first. A file still carrying one is ignored rather than warned about, so `repld gist lint`'s `legacy` rule is now the only thing that reports it. Two things get better as a result — a tool taking a single `dict` argument works now (it was indistinguishable from the old `handler(args)` shape and silently skipped), and a file mixing both conventions no longer has its typed functions suppressed.
- **`repld[browser]` now requires Chrome 140+.** `Tab.fetch()`'s hand-chunked `btoa` fallback for browsers without `Uint8Array.prototype.toBase64` is gone; that method has been on by default since Chrome 140 and Baseline since September 2025, and only binary response bodies ever touched the path.
- Dead compatibility branches and `.gitignore` scaffolding: `repld init` no longer writes `.pyrepl.*` ignore entries, since nothing repld writes at runtime lands in the project directory. Existing lines are harmless and can be deleted.

## [0.1.1] - 2026-07-24

### Added

- `repld gist lint [name...]` — AST-based best-practices checker for gist files. Four rules: `firstline` (module docstring's first line must stand alone — it's what gets truncated into tool listings/instructions/resource descriptions), `shape` (public methods returning dict/list/Any should document the return shape on the docstring's first line), `deps` (non-stdlib imports should be declared in `__repld_deps__`), `legacy` (flags `__repld_tools__` statically instead of only warning reactively at tool-call time). Documented in `repld://docs/guide`'s Conventions section, `repld help gists`, and `repld help`'s command list

### Fixed

- Console-error and dashboard-connect channel notifications built short target IDs (e.g. `9222:5CA9D0`) from the raw CDP `targetId` without lowercasing, unlike the canonical `make_target()` helper — an ID copied straight from a notification would fail every `browser_*` tool call, since `_is_target_id()`'s classifier regex only matched lowercase hex and silently misrouted the uppercase ID as a URL glob instead of a target ID (surfacing a confusing "no tab matching" error rather than something actionable). `_push_error_text` and the dashboard's connect summary now lowercase consistently with `make_target()`; `_is_target_id()`'s regex is case-insensitive and `_split_target()` normalizes its prefix, so any uppercase ID — from any source — now resolves instead of just being masked at the two known origins
- `install_deps()`'s tool-venv path (`uv pip install --target ~/.local/share/repld/deps`) resolved each newly-missing dep in isolation, blind to everything already installed in that shared, cross-project directory — two gists whose transitive deps disagreed (e.g. one pinning `pydantic==2.13.4`, needing `pydantic-core==2.46.4`, while a later install pulled a newer `pydantic-core` in unrelated to that constraint) could silently leave mutually-incompatible versions on disk. `gist_deps.py` now maintains a `.repld-manifest.txt` of every requirement ever installed there and re-resolves the full accumulated set on each install, not just the new arrivals
- `Tab._wait_for_node` cached the root `DOM.getDocument` nodeId once before its poll loop; a document replaced mid-wait (SPA navigation, HMR reload) left it stale, so `click()`/`type_text()`/`wait_for()` silently never matched and raised a misleading "Element not found" instead of surfacing the navigation race. Root nodeId is now re-fetched every poll iteration
- `gists.resolve_tool` could dispatch to a typed `_tool_*` function in a gist file that also declared unrelated legacy `__repld_tools__` entries — a case `scan_tools`/`tools/list` never advertised, since a legacy-declaring file suppresses all typed tools in that file. Both now share one `_declared_tools` classifier, so listing and dispatch agree
- `Tab._setup_binding` called `self._session.execute()` directly instead of `self._exec()`, skipping the session-gone recovery every other CDP call gets — pin setup could raise instead of self-healing across an HMR reload or navigation race
- `Tab.sse()` and `Tab.lifecycle()` ordered results by `ORDER BY rowid`, a column their underlying views never expose (only `id`) — both raised a DuckDB `BinderException` on every call
- Dashboard's per-pattern tab-count display recomputed glob matching in JS with a hand-rolled regex that always escaped `[`/`]`, diverging from the server's `fnmatch`-based watch matching — bracket-class patterns could show a stale count. Counts are now computed server-side in `BrowserPool.snapshot()` next to the actual match logic, and the client just renders them
- `gists._resolve_json_type` didn't unwrap parameterized generics (`list[str]`, `dict[str, int]`) when inferring an MCP tool schema from a `_tool_*` signature — fell through to the "unmapped type" warning and silently schema'd the param as `"string"`
- `gists.signature_for_path` (and `signature()`) picked a gist's *first* public class by file order for the "here's how to import this" hint, with no regard for whether it was the entry point — a custom exception type declared before the main class (a common pattern, e.g. `GigahostError(RuntimeError)` before `Gigahost`) would win instead, producing a hint that imported the wrong class. Now skips classes whose name or base ends in `Error`/`Exception`
- `gist_deps.scan_deps()` only ever ran once, at kernel boot — adding `__repld_deps__` entries to a gist file already imported by a long-running kernel never got checked or prompted again; you'd have to know to restart the whole kernel process to get the install prompt. `gists._check_reload()` now re-scans just the changed file's deps on every auto-reload, so a newly-declared dependency gets caught the next time the gist is (re-)imported instead of silently waiting for a restart. Also deduped `_GistImportHook`'s `base`/`top` reload checks (equal for any flat, non-package gist) so the new prompt can't double-fire for one reload
- `gist_deps.install_deps()` never pinned `--python` when installing into `_TOOL_DEPS_DIR` (the side-install dir used when repld runs as a global `uv tool install`, unlike the project-venv branch right below it, which already did). `uv pip install --target` with no `--python` resolves against uv's own default interpreter, which can silently differ from `sys.executable` — a binary wheel (`cffi`, `pydantic-core`, `rpds-py`, ...) built for the wrong Python ABI lands in the shared deps dir and fails with a bare `ModuleNotFoundError` for its compiled extension deep inside whatever imported it, nowhere near the actual cause. Now pins `--python sys.executable` in both branches
- A gist file created *after* the kernel had already booted skipped its `__repld_deps__` scan entirely on first import — `_GistImportHook`'s pre-import `_check_reload()` call is a no-op for a module `_GistFinder` has never resolved before (nothing in `_managed` to compare mtimes against yet), so only the boot-time scan (everything present at start) or a later edit (`_check_reload`'s own rescan) ever triggered it. "Write a new gist, `import` it right away" — an entirely normal same-session workflow — silently skipped the check, surfacing missing deps as a bare `ModuleNotFoundError` instead of an install prompt. `_GistFinder.find_spec` now runs the same scan the first time it tracks a `fullname`, across all three of its resolution tiers (local gist dirs, cross-project links, `path:` dep dirs)
- `gist_deps._is_importable()` only ever tried a dep's declared name verbatim (modulo `-`→`_`), so any package whose importable module name differs from its PyPI distribution name (`pyyaml`→`yaml`, `beautifulsoup4`→`bs4`, ...) was reported "missing" on *every* scan forever, install or not — the install itself succeeded harmlessly each time, but the kernel re-prompted on every boot and every first import indefinitely. Now falls back to `importlib.metadata.packages_distributions()`'s reverse mapping (distribution name → actual top-level import names) before giving up; the cache is dropped after `install_deps()` installs something so a same-session install is picked up immediately
- Kernel shutdown blocked up to 5 real seconds in `_browser_cleanup` whenever a browser had ever been attached: its atexit hook scheduled `real.disconnect()` on the kernel's asyncio loop via `run_coroutine_threadsafe`, but `_shutdown()` always stops that loop *before* atexit runs, so the coroutine had nothing left to drive it forward and the wait just ran out its 5s timeout every time. Because `_cleanup_lockfile`'s atexit hook (LIFO-ordered) runs *before* `_browser_cleanup`'s in practice, `.pyrepl.lock` was already deleted up to 5s before the process actually exited — a real window for a fresh `repld` invocation to start while the old kernel (and its IPC sessions) were still alive. `_browser_cleanup` now skips the coroutine dispatch entirely when the loop isn't running. Related: `ipc.Session._close_locked()` closed the raw socket but left its `rfile`/`wfile` `TextIOWrapper`s for GC/interpreter-shutdown finalization to close, which surfaced as an uncatchable `BrokenPipeError` ("Exception ignored in...") when their buffered flush hit the already-dead socket — both are now closed explicitly, with the same errors caught deliberately instead
- `Tab._reattach()` only recovers from CDP *session* invalidation (same target, new session — e.g. HMR reload); when a target is destroyed outright and replaced (a genuine cross-origin/site-isolation process swap), it still re-attaches by the old target id, so `Target.attachToTarget`'s raw CDP error ("No target with given id found") propagated straight out of `_exec()` uncaught, unexplained. Now catches that failure and raises a clear error pointing at `browser_tabs` to find the replacement, instead of passing Chrome's raw text through unchanged
- `repld/__init__.py`'s `TYPE_CHECKING` block stubbed `notify`/`defer`/`every`/etc. for `import repld; repld.notify(...)` gist patterns but never added `browser`, despite `kernel.py` genuinely injecting it into the module at runtime — every gist referencing `repld.browser` type-checked as an attribute-access error

- The dashboard's per-tab Detach button never worked: `BrowserPool.snapshot()` built target IDs without lowercasing while the detach lookup compares lowercased, so every click returned "Target not found"
- HMR/navigation re-attach built a brand-new CDP session, silently discarding the tab's event history, body-capture state, and pin/label state, and leaking the old session's DuckDB connection. Re-attach now preserves the session in place (same mechanism as Chrome-restart reconnect) and re-registers the label script
- `tap`/`swipe` and `browser_tree` bypassed the session-gone recovery wrapper, so touch input and tree reads failed permanently after an HMR reload while clicks recovered
- Every browser mutation tool polled a heavyweight DuckDB HAR view at 20Hz *synchronously on the kernel loop* while waiting for network idle; settle now reads an in-memory in-flight counter maintained on the event path
- `repld gist new -h` / `add -h` / `rm -h` treated `-h` as a gist name (or exited non-zero); they now print usage and exit 0
- Scaffolded gists (`repld gist new`) shipped an unused `import os` that lint flags in the user's project
- Doc drift: `repld help browser` claimed CSS selectors use `DOM.getBoxModel` (the code uses `DOM.getContentQuads`) and understated `ready=` as CSS-only (it also accepts JS expressions)
- Missing `task_id` on `get_task`/`cancel` returned a generic internal error (`-32603 KeyError`) instead of the proper invalid-params error (`-32602`)
- Multi-line `str` cell results print verbatim instead of being `repr()`-escaped into an unreadable single line with literal `\n`s
- `repld://gists/{name}` signature listings no longer render `@property`/`@cached_property` methods with call parens (was misleading agents into calling e.g. `.pid()` and getting a `TypeError`)
- `browser_fetch` / `Tab.fetch()` silently sent string bodies with no `Content-Type`, so the browser defaulted to `text/plain` and form-decoding servers saw an empty form — root cause was in `Tab.fetch()`'s header defaulting, not the MCP transport
- `browser_fetch` tool schema: `body` had no declared `type`, so MCP clients could silently flatten a dict argument to a JSON string instead of sending it as an object. Now typed `["object", "string"]`, matching what the handler actually accepts
- `no_display(value)` only unwrapped on a cell's bare last expression — direct assignment (`x = await foo()`) left `x` bound to the internal wrapper object instead of the real value, contradicting its own "still returning it... for programmatic use" contract. `compile_cell()` now also collects top-level simple-assignment targets (`x = ...`, chained `x = y = ...`, annotated `x: T = ...`) and `run_cell()` unwraps `_NoDisplay` off them after they're bound. Doesn't cover tuple/list/starred/attribute/subscript targets or walrus expressions nested in larger expressions
- `browser.watch(pattern)` silently reported "Attached 0 new tab(s)" when a matching target existed but the CDP `Target.attachToTarget` call failed (e.g. another debugger already attached to it) — the exception was swallowed and logged only at `DEBUG` (no logging is configured anywhere in the package, so it was never actually emitted). The returned summary now appends `N attach attempt(s) failed: <target>: <reason>` when any attach errors, instead of looking identical to "nothing matched the pattern"
- `BrowserJSError.stack` was always a copy of `.text` (never an actual stack trace), contradicting the docs' claim of a "preserved stack trace". Now parses CDP `exceptionDetails.stackTrace.callFrames` into a real multi-frame string
- Kernel boot swallowed dashboard-start, Chrome-port-reconnect, and pattern-re-watch failures with a bare `except: pass` — a broken dashboard import or failed session restore was invisible. Now logged to stderr
- `repld exec` had no `--socket` flag despite `repld bridge` supporting one, so pointing `exec` at a kernel on a non-default socket path required setting `REPLD_SOCKET` instead
- `Tab._wait_ready()` silently no-op'd on navigate/reload whenever `ready=` wasn't explicitly passed (the common case) — `self._ready` was `None` so the method returned immediately, skipping even the default `document.readyState === 'complete'` wait. Now falls back to that expression instead of returning early
- `Browser.detach(pattern=...)` (and detach-all) never unpinned tabs before detaching, unlike `detach_target()` — a pinned tab's pill, beforeunload guard, and heartbeat task leaked whenever it was detached via a pattern or `detach()` with no argument
- `resolve_gate()` could raise (or silently do nothing, depending on timing) when the terminal and a pinned tab's pill raced to resolve the same human-gate — `Future.set_result()` on an already-resolved future raises `InvalidStateError`, which wasn't caught. First responder now always wins cleanly
- Gist registry writes (`_register()`) crashed on a corrupt `gist-registry.json` instead of resetting it, unlike the read path (`registry()`); both now handle corruption the same way
- `_every_registry` (the set of active `@every` tickers) was mutated from the asyncio loop thread, sync-cell threads, and the dashboard's HTTP thread with no lock — the same missing-lock bug class as the task registry, just not yet hit in practice
- `_tasks` (the task registry) had no lock guarding it against concurrent watchdog-thread/IPC-reader-thread access; entries were also never evicted after completion, leaking forever in a long-running kernel. Now locked and evicted 1h after `done_event`
- `BrowserPool.get(target, timeout=N)` gave each connected Chrome instance the *full* timeout before trying the next one, so with N connected browsers a "not found" could take up to N×timeout instead of timeout total. Now shares one deadline across all browsers
- `Tab.capture_bodies` setter flipped the visible flag before `enable_fetch()`/`disable_fetch()` had actually finished (or even started, since the CDP call is fire-and-forget from a sync setter) — code reading `capture_bodies` right after setting it could see the new value while Fetch interception was still in its old state
- `_pick_victim` (the loop-watchdog's kill-candidate scan) iterated `tasks._tasks.values()` directly instead of a snapshot, risking a `RuntimeError: dictionary changed size during iteration` if a task was added or finalized mid-scan
- `hint_for_name()` (the "did you mean to import this gist?" suggestion) only scanned `_installed_dirs`, so it never suggested a gist that was only present via cross-project linking (`repld gist add`)
- `observe.py`'s iframe-tree attachment matched on a substring of the accessible name, so any node whose name happened to contain "Iframe" could be misattached as a child iframe's tree root
- `gists.install()` didn't update the existing `_GistFinder`'s directory list on repeat calls (e.g. after `repld gist add`), leaving the finder stale while `_installed_dirs` (and therefore `_find_gist`/`_iter_gist_files`) had already moved on
- `Tab.cdp()` (the raw-CDP passthrough MCP tool) called the session directly instead of going through `_exec`, so it — unlike every other `Tab` method — couldn't recover from a stale session after an HMR reattach
- `resolve_tool()` let a broken gist's import error escape `tools/call` instead of failing soft with a warning, the way `scan_tools()` already does for `tools/list`
- `_Tee.write`'s lazy spill-file open had no lock, so two threads sharing a `task_id` (a sync cell's `asyncio.to_thread` worker racing the loop thread) could both open the spill file, leaking the first handle and losing its output; `Tab.pin()` checked-then-set `_pinned` across two `await`s, so a concurrent `pin()` call could pass the guard twice and leak a heartbeat task that later reset `_pinned=False` out from under the real one; `CDPSession.enable_fetch()`/`disable_fetch()` had the same check-await-set gap
- `browser.get(<target-id>)` raised `TabNotFoundError` when another `attach()` was already in flight for that exact target, instead of retrying like the glob-based lookup does — extracted the shared poll interval into `_ATTACH_POLL_INTERVAL_S`
- `Browser.detach_target()` let unpin/detach exceptions propagate while `detach()` swallowed them — same operation, inconsistent error handling; both now go through one `_unpin_and_detach()` helper
- `Tab.fetch()` / `browser_fetch` always read the response as `r.text()`, so binary payloads (ZIP, PDF, image, protobuf) came back as mangled mojibake instead of the actual bytes. Now reads `arrayBuffer()` and probes UTF-8 validity via `TextDecoder(..., {fatal: true})` — text responses are unchanged (JSON still auto-parsed), invalid UTF-8 is base64-encoded (native `Uint8Array.prototype.toBase64()` when available, chunked `btoa` fallback otherwise) and returned as `base64Encoded: true`, matching the `{body, base64Encoded}` shape `tab.body()` already uses
- `gists.py`'s tool-schema builder silently mapped any unrecognized parameter type (e.g. `bytes`, `Path`, `Optional[str]`) to JSON Schema `"string"` with no warning, unlike every other malformed-input path in the file; `gist_deps.py`'s `__repld_deps__` scanner had the same silent-fallback gap for non-list values
